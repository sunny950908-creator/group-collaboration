# STATUS 的測試證據

在專案目錄執行 `python /absolute/path/groupctl.py status`，或向本機 agent 下達 `STATUS`。

STATUS 會抓取遠端資訊，從目前 HEAD 與 origin 各遠端追蹤分支的已提交事件探索已發布的協作紀錄，不會自動整合功能分支。

| 輸出欄位 | 意義 |
| --- | --- |
| `commit` | 目前 HEAD 的完整提交雜湊。 |
| `test_results` | 所有探索到的已發布 `test_result`，保留原有內容及語意，可能包含目前版本與其他版本的歷史證據。 |
| `current_commit_test_results` | `test_results` 中，事件的 `commit` 與本次輸出的 `commit` 完全相等者；沒有符合事件時為空陣列 `[]`。 |

例如 HEAD 為提交 B，事件只測試過其祖先 A，則該事件仍列在 `test_results`，但不會列在 `current_commit_test_results`。其他分支若發布了針對同一個完整提交 B 的測試事件，仍可列入目前版本的證據；不以發布者或分支名稱判定。

## 限制

- 新欄位只篩選精確相同的提交，不推論祖先、相同檔案內容、縮寫雜湊或其他版本的測試結果可適用於 HEAD。即使只新增文件或中繼資料提交，也必須重新符合精確提交條件。
- 發布測試事件本身會新增提交，因此剛執行 TEST 後，目前 HEAD 可能已不同於被測提交，新欄位仍可能為空。空陣列表示沒有發現符合的已發布證據，不表示測試失敗。
- 此欄位包含符合提交的所有測試結果，包括失敗、部分完成或無可用檢查的結果；非空不代表通過，必須閱讀 `automated_result`、命令輸出與人工檢查需求。
- STATUS 不會執行測試，也不驗證事件聲明的真實性。測試證據只描述已提交快照，不涵蓋工作目錄尚未提交的修改，也不等於語意審查通過。
- 這是 CLI 輸出的新增欄位，沒有變更事件協定、`test_result` 格式或既有欄位語意。
